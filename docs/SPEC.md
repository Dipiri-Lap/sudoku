# 보석 왕국 — 규칙 명세

로얄매치 / 로얄킹덤 계열 3매치의 규칙 명세.
**컨셉은 보석이지만 엔진에 색은 인덱스일 뿐이라, 컨셉을 바꿔도 이 문서는 그대로다.**

## 이 문서의 사용법

이 문서가 **유일한 판단 기준**이다. "이게 재미있나?"(사람만 판정 가능)를
"레퍼런스와 같게 동작하나?"(기계가 판정 가능)로 바꾸는 것이 목적이다.

| 표시 | 뜻 |
|---|---|
| ✅ | 구현됨 + 테스트 있음 |
| 📖 | **출처로 확인됨** + 미구현 → 다음 할 일 |
| 🔶 | 출처를 못 찾음 → 직접 플레이해서 확인 필요 |
| ⬜ | 우리가 정할 것 (레퍼런스에 매이지 않는 부분) |

규칙을 바꾸려면 **`engine/specials.ts` 상단의 표만** 고친다. 로직은 표를 읽을 뿐이다.

## 조사 요약 (2026-08-25)

> **로얄킹덤의 코어 퍼즐은 로얄매치와 동일하다.** 아이템(브레이커)의 생성·발동
> 방식이 완전히 같고, 장애물은 로얄매치 장애물의 리스킨으로 동작도 같다.
> 차이는 코어 밖에 있다 — 난이도 곡선, 골렘 같은 신규 장애물, 10레벨마다의
> 킹덤 레벨(PvE).

→ **코어 엔진은 로얄매치 규칙 하나만 정확히 구현하면 된다.** 로얄킹덤은
그 위의 레벨 구성과 장애물 추가로 갈린다. (9장 참고)

## 5. 아이템 합체 — 📖 전부 확인됨, 전부 미구현

**두 아이템을 서로 스왑했을 때.** 조합이 유한해서 표 하나로 명세되고
테이블 테스트로 완전히 커버된다. **자동 루프에 맡기기 가장 좋은 작업.**

| A + B | 효과 |
|---|---|
| 로켓 + 로켓 | 합쳐진 칸의 **행과 열 모두** (십자) |
| 로켓 + TNT | **3개 행 + 3개 열** |
| 로켓 + 라이트볼 | 보드에서 **가장 많은 색**을 전부 **로켓으로** 바꾼다 |
| TNT + TNT | **반경 4 (9x9, 약 80칸)** |
| TNT + 라이트볼 | 가장 많은 색을 전부 **TNT로** 바꾼다 |
| 프로펠러 + 로켓 | 프로펠러가 **로켓을 싣고** 목표물 많은 칸으로 날아간다 |
| 프로펠러 + TNT | 프로펠러가 **TNT를 싣고** 날아간다 |
| 프로펠러 + 프로펠러 | **프로펠러 3개**를 만들어 무작위 목표 3곳을 친다 |
| 프로펠러 + 라이트볼 | 가장 많은 색을 전부 **프로펠러로** 바꾼다 |
| 라이트볼 + 라이트볼 | 보드의 **모든 요소** 제거 + **모든 장애물의 한 겹** 제거 |

> **라이트볼 합체는 "스왑한 상대 색"이 아니라 "보드에서 가장 많은 색"을 노린다.**
> 단독 발동(4.3)과 기준이 다르다. 헷갈리기 쉬운 지점.

## 6. 장애물 — 📖 분류 확인됨, 데이터 모델만 구현

로얄킹덤 기준 **33종 이상**. 종류를 하나씩 나열하는 대신 **동작 축**으로 모델링해야
한다. 리스킨만 다른 같은 동작이 대부분이기 때문이다.

| 축 | 뜻 | 상태 |
|---|---|---|
| **겹(Layers)** | 여러 번 맞아야 없어진다. 최대 8겹 이상 | ✅ `Blocker.layers` |
| **아이템 전용** | 일반 매치로는 안 부서지고 아이템만 통한다 | ✅ `powerUpOnly` |
| **색 지정** | 특정 색으로만 처리된다 | ✅ `color` |
| **숨김(Hidden)** | 다른 걸 치워야 드러난다 | ⬜ 필드만 있음 |
| **바닥(Bottom)** | 아래로 떨어뜨려 판 밖으로 빼내야 한다 | ⬜ 중력 처리와 얽힘 |
| **이동(Moving)** | 매 턴 스스로 움직인다 (로얄킹덤 골렘 등) | ⬜ **훅 자리는 생김** (`onTurnEnd`) |
| **생성(Produce)** | 매 턴 무언가를 뱉어낸다 (우편함→편지) | ⬜ 훅으로 구현 |
| **보조(Helper)** | 플레이어를 돕는 요소 | ⬜ |

| # | 규칙 | 상태 |
|---|---|---|
| 6.1 | 인접한(상하좌우) 매치로 한 겹 부서진다. 대각선은 안 통한다 | ✅ |
| 6.2 | **한 번의 clear에서 같은 장애물은 최대 한 겹만 깎인다** | ✅ 🔶 |
| 6.3 | 덮개는 보석 대신 맞는다 — 다 벗겨야 그 보석이 없어진다 | ✅ 🔶 |
| 6.4 | 장애물·구멍은 열을 위아래로 끊는다 — 아래 구간은 새 보석을 못 받는다 | ✅ |
| 6.5 | 아이템 폭발이 장애물을 관통하는가, 거기서 멈추는가 | 🔶 현재는 관통 |
| 6.6 | 한 레벨에 장애물이 2~4종 섞여 나온다 | 📖 |

> **6.2가 왜 중요한가**: 칸마다 세면 로켓 하나가 벽을 따라 지나갈 때 인접 칸이
> 여러 개 터지면서 8겹짜리 장애물이 한 방에 사라진다. 그래서 clear 단계마다
> 장애물당 한 겹으로 제한했다. 레퍼런스가 정말 그런지는 확인 필요.

> **"이동" 축이 구조적으로 제일 무겁다.** 턴이 끝난 뒤 보드가 스스로 바뀌는
> 훅이 필요한데, 지금 `resolveTurn`에는 그 자리가 없다. 골렘을 넣으려면
> 단계 목록에 `board-effect` 같은 단계가 추가돼야 한다.

### 7.7 난이도 — 봇으로 자동 검증할 기준

| 항목 | 값 | 출처 |
|---|---|---|
| 로얄매치 하드 레벨 비율 | **10레벨당 2개** | 📖 |
| 로얄킹덤 하드 레벨 비율 | **10레벨당 4개** | 📖 |
| 난이도 사이클 | **5~10레벨 주기**, 각 사이클 첫 레벨은 쉽게 | 📖 |
| 난이도 지표 | 클리어까지 걸린 시도 횟수. 쉬움 1~3회, 어려움 20~35회 | 📖 |

> **이게 봇 검증의 목표값이다.** 레벨을 만들면 봇이 수천 판 돌려
> "평균 시도 횟수"를 내고, 그 레벨이 의도한 난이도 구간에 들어오는지 자동 판정한다.
> 사람은 숫자를 정하고, 판정은 기계가 한다.

## 8. 연출 — 규칙 아님 (사람이 수치화)

기계가 판정할 수 없는 유일한 영역. **레퍼런스를 보고 사람이 숫자로 옮겨 적으면,
그 순간부터 상수가 되어 테스트가 지킬 수 있다.**

| # | 항목 | 값 |
|---|---|---|
| 8.1 | 스왑 슬라이드 시간 | 🔶 |
| 8.2 | 매치 터짐 시간 | 🔶 |
| 8.3 | 빈칸을 보여주는 정지 구간 | 🔶 |
| 8.4 | 낙하 속도 (N칸당 몇 초) | 🔶 |
| 8.5 | 착지 스쿼시 유무 | 🔶 |
| 8.6 | 로켓 궤적 / 폭발 연출 길이 | 🔶 |

> 기존 `royal-match`에서 얻은 교훈: 낙하 시간을 √거리에 비례시키고 이징을
> 이차 ease-in으로 두면 모든 타일이 같은 가속도로 떨어져 서로 추월하지 않는다.
> 이 조합을 깨면 같은 열의 타일이 겹쳐 보인다.
