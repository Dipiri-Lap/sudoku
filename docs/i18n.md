# i18n conventions (ko / en / ja / de / es / fr / pt / zh)

Korean is the source language and its URLs never change. Every other language lives under its own prefix.
Library: `i18next` + `react-i18next`, resources bundled statically (no HTTP loading).

| code | language | URL prefix | `<html lang>` | `intlLocale` (dates) | switcher name |
|---|---|---|---|---|---|
| `ko` | Korean (source) | none | `ko` | `ko-KR` | 한국어 |
| `en` | English | `/en` | `en` | `en-US` | English |
| `ja` | Japanese | `/ja` | `ja` | `ja-JP` | 日本語 |
| `de` | German | `/de` | `de` | `de-DE` | Deutsch |
| `es` | Spanish | `/es` | `es` | `es-ES` | Español |
| `fr` | French | `/fr` | `fr` | `fr-FR` | Français |
| `pt` | Brazilian Portuguese | `/pt` | `pt-BR` | `pt-BR` | Português |
| `zh` | Traditional Chinese | `/zh` | `zh-Hant` | `zh-TW` | 繁體中文 |

The table lives in code: `LANGS` + `LANG_META` in `src/i18n/locale.ts` (not in translation json).

## How the language is chosen

- Language comes from the first URL segment: `/en[/*]` → `en`, `/de[/*]` → `de`, … everything else → `ko`.
- Browser language → supported language (`browserLangToSupported(navigator.language)` in `locale.ts`):
  `ko*` → ko, `ja*` → ja, `de*` → de, `es*` → es (incl. es-MX …), `fr*` → fr (incl. fr-CA …), `pt*` → pt
  (incl. pt-PT), `zh-TW` / `zh-HK` / `zh-MO` / `zh-Hant*` → zh, **anything else → en** (incl. `zh-CN`,
  `zh-SG`, `zh-Hans`, `it`, …).
- Home page `/` only: the inline `<script>` at the top of `index.html`'s `<head>` (ES5, keep it tiny) reads the
  saved choice `localStorage.lang_pref` (one of the 8 codes, written by `saveLangPref()` from the switcher and the
  banner): `ko` → stay, other code → `/<code>/`. With no saved choice it applies the same mapping as
  `browserLangToSupported` (duplicated there — keep both in sync). Bots/headless UAs are skipped.
- Game URLs are never auto-redirected. On **Korean pages only** `LanguageVersionBanner` shows, for a non-Korean
  browser, a one-line banner in the browser's (mapped) language linking to the same page in that language
  (`switchLanguageUrl`). Its text is `LANG_BANNER_TEXT` in `locale.ts` (one sentence + "close" label per language,
  written in code so it works before the json is translated). Dismissing it (= `lang_pref` `ko`) or picking any
  language hides it for good.
- `src/main.tsx` imports `./i18n` first, then renders `<BrowserRouter basename={routerBasename}>`
  (`'/en'`, `'/de'`, …, `undefined` in Korean). `document.documentElement.lang` is set to `LANG_META[lang].htmlLang`
  at startup (`pt-BR`, `zh-Hant`, …).
- Switching language = full page load to `switchLanguageUrl(lang)` (the language never changes at runtime).
- Language switcher (`LanguageSwitcher.tsx`, landing profile bar): a small pill (globe + current native name) that
  opens a listbox of all `LANGS` with `LANG_META.nativeName`. The list is portalled to `<body>` with fixed
  positioning. Keyboard: ↓/↑ on the button opens, ↑/↓/Home/End move, Enter/Space picks, Esc/Tab/outside click closes.

## Files

| What | Where |
|---|---|
| init + resource registry | `src/i18n/index.ts` |
| key typing (from ko json) | `src/i18n/types.d.ts` |
| URL/lang helpers, feature flags | `src/i18n/locale.ts` |
| strings | `src/locales/{ko,en,ja,de,es,fr,pt,zh}/{namespace}.json` |

Namespaces (one per area — only edit your own):

| ns | used by |
|---|---|
| `common` | brand, game names (`games.<id>.name`), shared difficulty labels, app shell, language UI |
| `landing` | `src/common/components/LandingPage.tsx` |
| `sudoku` | `src/features/sudoku/**` |
| `queens` | `src/features/queens/**` (Crown Quest) |
| `jigsaw` | `src/features/jigsaw/**` (Tiny Pieces) |
| `snapspot` | `src/features/snapspot/**` |
| `modals` | CoinShopModal, LoginModal, ProfileModal, TermsModal, CoinDisplay, CoinRewardToast |
| `daily` | `src/features/daily/**` (calendar, push prompt). The sudoku daily result modal keeps its strings in `sudoku:game.daily*` / `monthComplete` |

All 8 namespaces exist in all 8 languages and are registered in `src/i18n/index.ts` — just fill them.
A brand-new namespace needs an import + entry for every language in `resources` there.

Translator file list (one file per namespace per language; de/es/fr/pt/zh start as `{}`):

```
src/locales/<lang>/common.json   landing.json   sudoku.json   queens.json
                   jigsaw.json   snapspot.json  modals.json   daily.json
<lang> = de | es | fr | pt | zh          (ko = source, en/ja = already translated, use en as the source)
```

Fallback:
```ts
fallbackLng: { ja: ['en','ko'], de: ['en','ko'], es: ['en','ko'], fr: ['en','ko'], pt: ['en','ko'], zh: ['en','ko'],
               default: ['ko'] }
```
A key missing in any non-English language shows **English** (then Korean if English is missing too); a key missing
in `en` shows Korean. So an empty `<lang>/<ns>.json` is safe — the page is English until translated. Never let a new
language fall straight to Korean (that is what `default` does — add it to the map).
Data lookups outside `t()` (`stageTitle()`, `localizedData.ts`) walk `i18n.languages`, i.e. the same chain.

Reuse from `common` instead of duplicating:
- game names: `games.sudoku|queens|jigsaw|snapspot|wordSort|crossMath|arrowPuzzle|daily.name`
  (en: Sudoku, Crown Quest, Tiny Pieces, SnapSpot, Word Stack, Crossum, Arroway, Daily Puzzle;
  ja: 数独, クラウンクエスト, タイニーピース, スナップスポット, ワードスタック, クロッサム, アロウェイ, 今日のパズル —
  "ナンプレ" only in SEO copy, never as the name)
- `brand` (퍼즐 가든 / Puzzle Garden / パズルガーデン)
- `difficulty.veryEasy|easy|beginner|medium|hard|expert|master`

## Rules

1. **ko json must reproduce today's Korean exactly** — same characters, spacing, punctuation, emoji.
   The Korean UI must not change by a single character. Copy-paste, don't retype.
   JSX text split over lines collapses to one space: `foo\n   bar` in JSX → `"foo bar"` in json.
2. **en**: natural, short, casual-game tone. Not literal. Keep brand names (SnapSpot, Tiny Pieces, Crown Quest).
   **ja**: natural casual-game Japanese, translated from the meaning (en is usually the better source than ko).
   です/ます for sentences and messages, plain nouns for short labels/buttons. Use the katakana game names above.
   Difficulty: とてもやさしい / やさしい / 初級 / ふつう / むずかしい / エキスパート / マスター (`common.difficulty`).
   **de / es / fr / pt / zh**: translate from en (meaning, not words), natural casual-game tone of that market.
   de: informal *du*; es: neutral Spanish, *tú*; fr: *vous* in messages is fine, keep it light; pt: Brazilian
   Portuguese, *você*; zh: Traditional characters with Taiwan usage (e.g. 遊戲, 關卡, 提示), full-width punctuation.
   Brand names stay Latin unless a market name is decided (the Crown Quest page hides its h1 when
   `games.queens.name` is exactly `Crown Quest`, because the logo already says it).
   Strings are often longer in de/fr/es/pt — keep buttons short.
3. Keys: nested camelCase by screen/feature, e.g. `modeSelect.title`, `result.clearTitle`, `tutorial.step1.desc`.
   No full sentences as keys. Same key set in every language.
4. Keys are type-checked against the **ko** json (typos fail `tsc`). Add the ko string first.
5. Dev-only / localhost-only screens and `console.*` text: leave Korean, don't translate.

## Usage

```tsx
import { useTranslation, Trans } from 'react-i18next';

const { t } = useTranslation('queens');          // your namespace
const { t: tc } = useTranslation('common');      // shared strings

t('modeSelect.title')
tc('games.queens.name')
t('result.stage', { n: stage })                  // json: "스테이지 {{n}}" / "Stage {{n}}"
t('result.moves', { count })                     // plural, see below
t(`difficulty.${key}`)                           // dynamic key OK if `key` is a typed union
```

Inline markup — use `<Trans>` (basic tags `<br/>`, `<strong>`, `<i>`, `<p>` work as-is in json):

```tsx
// json: "body": "보드를 <strong>모두</strong> 채우세요.<br/>행운을 빌어요!"
<Trans t={t} i18nKey="tutorial.body" />
// custom tags with styling:
// json: "progress": "이번 달 <green>{{cleared}}</green> / {{total}} 완료"
<Trans t={t} i18nKey="daily.progress" values={{ cleared, total }}
       components={{ green: <span style={{ color: '#16a34a' }} /> }} />
```

Plurals (i18next uses `Intl.PluralRules` suffixes):

| language | suffixes to define |
|---|---|
| ko, ja, zh | `_other` only |
| en, de, es, fr, pt | `_one` + `_other` |

French and Portuguese (pt-BR) count **0 as `_one`** ("0 coup", "0 jogada"); English/German/Spanish use `_other` for 0.
(es/fr/pt also have a `_many` category, used only for exact multiples of 1 000 000 — counts this app never shows;
without a `_many` key such a count would fall back to English, so don't bother adding it.)

```json
// ko / ja / zh
{ "moves_other": "{{count}}번 이동" }
// en
{ "moves_one": "{{count}} move", "moves_other": "{{count}} moves" }
// de
{ "moves_one": "{{count}} Zug", "moves_other": "{{count}} Züge" }
```
Call `t('moves', { count })`. Always pass the number as `count`.

Outside React (utils, constants, services, toasts fired from plain functions):

```ts
import i18n from '../../i18n';
i18n.t('queens:toast.saved');            // "ns:key"
i18n.t('toast.saved', { ns: 'queens' }); // same
```
Init is synchronous and the language is fixed per page load, so module-level `i18n.t(...)` works,
but prefer calling `t` at render time.

Dates: pass `intlLocale` from `locale.ts` (`ko-KR`, `de-DE`, `pt-BR`, `zh-TW` …) to `Intl.DateTimeFormat` /
`toLocaleDateString` — never `i18n.language` (`pt`/`zh` are ambiguous) and never a hard-coded locale.

Arrays of tutorial steps etc.: keep the structure in TS, put only the strings in json
(`steps: [{ titleKey: 'tutorial.step1.title', ... }]` → `t(step.titleKey)`), or build the array inside
the component with `t(...)`.

## URLs and links

- `<Link to="/queens/play">` and `navigate('/queens/play')` already get `/en`, `/de`, … from the router basename. Don't add it.
- Anything that bypasses the router needs `localeHref`:

```ts
import { localeHref, localeAbsoluteUrl } from '../../i18n/locale';
<a href={localeHref('/sudoku')}>…</a>
window.location.href = localeHref('/queens');
const shareUrl = localeAbsoluteUrl('/snapspot');   // https://…/en/snapspot, https://…/de/snapspot, unchanged in Korean
```
`localeHref` is a no-op in Korean and leaves external URLs / `#hash` alone.
- Static assets (`/images/...`, `/sounds/...`) are not localized — never wrap them.

## Feature gating outside Korean (phase 1)

```ts
import { isKo, isEn, isJa, currentLang, LANG_META, intlLocale, paidCoinsEnabled, isGameAvailable, INTL_AVAILABLE_GAMES } from '../../i18n/locale';
// INTL_AVAILABLE_GAMES = ['sudoku', 'queens', 'jigsaw', 'snapspot']   (EN_AVAILABLE_GAMES is a deprecated alias)
```
- **Daily** (`/daily`) is gated per month: `isDailyAvailable(monthKey?)` in `locale.ts` (default = the user's local
  current month) is true in Korean, and outside Korean only when that month's game (`DAILY_MONTHS` in
  `src/features/daily/data/months.ts`) is in `INTL_AVAILABLE_GAMES`. `isGameAvailable('daily')` uses the same rule, so
  App route gating, the landing block and `switchLanguageUrl` follow it. Word Stack months stay Korean-only.
- The list applies to **every non-Korean language**. Not available outside Korean: word-sort, crossword, daily,
  cross-math, arrow-puzzle, guide, others. `App.tsx` redirects any `/<lang>/<route>` whose first
  segment is not in the list to that language's home. Hide entry points to them with `isGameAvailable('<route-id>')`
  (e.g. "go to daily" buttons, cross-promo). `switchLanguageUrl(lang)` sends an unavailable game to that language's home.
- `paidCoinsEnabled` (`= isKo`) is `false` outside Korean: hide PortOne/KRW coin packs and any "buy" UI. Ad/free
  rewards can stay.
- **Which flag to use:** "international / not the Korean site" (hide Korean-only features, KRW payments,
  international privacy sections, Korean-only guide links, layout that assumes short Korean strings) → **`!isKo`**.
  Use `isEn` / `isJa` / `currentLang === 'de'` only for behaviour that is truly specific to that one language.
  Never use any of them to pick strings — that's what json is for — and never assume "not ko and not en = ja".

## Adding another language (checklist)

1. `src/i18n/locale.ts`: add the code to `LANGS`, a `LANG_META` row (prefix, htmlLang, intlLocale, nativeName) and a
   `LANG_BANNER_TEXT` row; extend `browserLangToSupported` if the browser tag needs special mapping.
   Basename, `localeHref`, `switchLanguageUrl`, the switcher list and the banner follow automatically.
2. `src/locales/<code>/*.json` for every namespace (`{}` to start), imports + `resources` entry in
   `src/i18n/index.ts`, and a `fallbackLng` entry `['en', 'ko']`.
3. `index.html` inline script at the top of `<head>`: add the code to its `langs` list (and mirror any special
   browser mapping).
4. Prerender / sitemap / hreflang (`scripts/seo-routes.mjs`, `scripts/prerender.mjs`, `scripts/generate-sitemap.mjs`,
   hreflang `<link>`s in `index.html`).
5. Push: `functions/src/dailyPush.ts` (`PushLang`, `PUSH_LANGS`, `TEMPLATES`, `MONTH_REWARDS` titles) + tests.
   The client stores whatever `LANGS` contains as the token's `lang`.
6. Fonts: the display fonts are Black Han Sans (Hangul + basic Latin only — **no accented Latin**, no `·`) and
   Lilita One (full Latin-1/Latin Ext). Every Black-Han-Sans-first stack falls back to `"Arial Black", 'Lilita One'`
   for accented letters. Kana/Han: `"M PLUS Rounded 1c"` (web font, loaded only under `/ja`) and
   `"Chiron GoRound TC"` (web font, loaded only under `/zh`, both from `src/i18n/index.ts`), then JP system fonts,
   then `"PingFang TC", "Microsoft JhengHei", "Noto Sans TC"`. Under `/zh` (`html:lang(zh-Hant)`) the body stack in
   `src/index.css` puts the TC system fonts before the JP ones. A new script needs the same treatment.
7. Plural suffixes for the language (see Plurals) and a line in the table at the top of this file.

## Verify

```sh
node --max-old-space-size=8192 ./node_modules/typescript/bin/tsc --noEmit -p tsconfig.app.json
npm run build          # includes prerender + sitemap (postbuild)
npm run dev            # then check both:
#   http://localhost:5173/<game>      Korean, must look exactly as before
#   http://localhost:5173/en/<game>   English, no Korean left on screen
#   http://localhost:5173/ja/<game>   Japanese (English where ja keys are still missing), no Korean
#   http://localhost:5173/de/<game>   (es, fr, pt, zh the same) English until translated, never Korean
```
Quick leftover-Korean check for your feature (ignore comments/dev-only lines):
```sh
rg -n "[가-힣]" src/features/<game> -g "*.tsx" -g "*.ts" | rg -v "^\S+:\d+:\s*(//|\{/\*|\*)"
```
Also diff key sets — every key in `ko/<ns>.json` must exist in `en/<ns>.json` (missing en keys
silently fall back to Korean) and in every other `<lang>/<ns>.json` (missing keys fall back to English).
Plural keys differ by language (`_one` exists only in en/de/es/fr/pt), so compare without the plural suffix.
